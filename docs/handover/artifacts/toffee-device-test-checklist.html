  • 배포 대기: 10-20에 Claude가 고친 것(읽음 줄·번역 판별·차단 안내·배경 다크·모니터링 격자·CP 인용의 팬 이름 자리 등)은 브랜치에만 있어요. 메모에 "배포 후 다시 확인"이라고 적힌 항목은 main 반영·배포 뒤에 봐 주세요.
  • 남은 항목은 모두 main이 데모 서버에 배포된 상태 + 운영자 → 데모 초기화 1회를 기준으로 써 있어요. PC 웹(demo.toffeechat.app)은 이것만 하면 바로 확인돼요.
  • 폰 태그 항목은 앱을 새로 빌드해서 설치한 뒤에 확인해 주세요(10-12~10-14 수정분이 다 들어간 빌드). 지금 앱에서 안 보이면 건너뜀으로 두세요.
  • 10-20 저녁 추가분(운영자 홈 통계·토피룸 모니터링·등록 화면·금칙어/신고/회원 개편, 운영 기능 9개 — 1:1 문의·내 정보 받기·점검 모드·공지 푸시·계약일·2단계 인증 등)도 main에 들어갔어요. 항목 제목 끝에 (10-20 운영)이 붙은 것들이에요. 폰 태그 항목은 앱이 업데이트(새 빌드 또는 OTA)된 뒤에 확인해 주세요.
  • 10-20까지 고친 것(일괄 등록·예약 오픈·스페인어/포르투갈어·긴 메시지 전체보기 등)은 모두 main에 들어가 있어요 — 데모 서버·웹이 배포된 뒤 확인해 주세요. 설정 → 언어에 Español이 보이면 배포된 거예요.

시작 전에

폰: 설치한 Toffee Dev 앱 · PC: demo.toffeechat.app (같은 데모 서버라 서로 연결돼요). 폰으로 팬, PC로 아티스트를 같이 켜 두면 푸시·실시간 확인이 쉬워요.

데모 계정은 로그인 화면 아래 데모 로그인 칸에서 들어가요. [소속사] [아티스트] [팬] 버튼을 고르고 입장 코드만 넣으면 돼요(이메일 입력 없음). 아래 표에서 버튼이 없는 계정(팬 2·이전 소속사)은 [이메일로]를 골라 이메일 + 입장 코드. 입장 코드는 Railway → toffee → Variables → DEV_LOGIN_CODE(눈 아이콘), 또는 운영자 화면 "데모 입장 코드"에서 만든 소속사용 코드도 돼요.

운영자로 들어가는 주소 — 운영자 버튼은 숨겨져 있어요. demo.toffeechat.app/?as=admin 으로 열면 [운영자] 칸이 나오고, 아래 운영자 입장 코드를 넣어요(브라우저에 기억 안 됨, 매번 입력).

운영자 입장 코드 — admin@toffee.demo는 위 입장 코드가 아니라 이 코드로만 들어가요(Railway DEV_LOGIN_ADMIN_CODE와 같은 값). 외부 소속사에 주지 마세요.

이 칸은 본인만 볼 수 있는 곳에 저장돼요(공유해도 다른 사람에겐 안 보임). Claude에게도 보내지 않아요.

데모 초기화 방법

테스트로 생긴 메시지·구독·계정을 지우고 처음 데모 상태로 돌려요. 테스트 시작 전 한 번, 다 하고 맨 마지막에 한 번 하세요.

  1. PC에서 demo.toffeechat.app/?as=admin → [운영자] → 운영자 입장 코드
  2. 운영자 첫 화면을 맨 아래까지 내려서 데모 초기화 누르기
  3. 확인 창에서 초기화 → "초기화하는 중…"이 끝날 때까지 기다리기(10초 안팎)
  4. 폰 앱: 프로필 → 로그아웃 → 다시 로그인(소셜 계정은 새로 만들어지고 푸시 등록도 다시 됨)

지워지는 것: 메시지·답장·신고·차단·구독·환불·정산 마감, 새로 만든 아티스트·CP·묶음·소속사, 소셜 로그인으로 생긴 계정, 폰 푸시 등록. 그대로: 데모 계정 6개, 앱 설치, 서버 설정, 이 체크리스트 결과.

버튼이 안 보이거나 실패할 때: Railway → toffee → Variables → DEMO_SEED를 reset으로 바꾸고 Deploy → 배포가 끝나면 다시 true로 바꾸고 Deploy(이걸 안 하면 배포할 때마다 초기화됨).
