## 보내기 전 체크리스트

순서가 중요하다 — 데모가 덜 된 상태로 보내면 첫인상을 되돌릴 수 없다.

1. **데모가 끝까지 되는지** — 파일 저장소(R2)는 2026-10-13 연결됨. 보내기 직전에 운영자 화면 "데모 초기화"(또는 Railway에
   `DEMO_DAILY_RESET=true`로 매일 새벽 자동)로 깨끗하게 만들고, **그 소속사 코드로 만든 링크 3개를 직접 눌러** 소속사·아티스트·팬 화면을 한 바퀴 돌려 본다.
2. **소속사별 입장 코드 만들기**(2026-10-19~) — 운영자 홈 "데모 입장 코드"에 소속사 이름·만료일(예: 보내는 날 + 4주)·메모. 접속 알림
   메일은 Resend 키를 Railway에 넣어야 온다(그 전엔 서버 로그). *(아래는 10-15까지의 공용 코드 시절 설명 — 데모 계정은 지금도 모든 소속사가 같이 씀)*
   **체험용 계정은 소속사마다 따로 만들 필요 없음** — 데모 데이터는 전부 가상이라 모든 소속사가 같은 데모 계정 3개(팬 `fan1@toffee.demo`,
   아티스트 `caramel-self@toffee.demo`, 소속사 `staff@toffee.demo`)와 같은 입장 코드를 쓴다(2026-10-15부터 로그인 화면의 역할 버튼·링크가 이 계정으로 들어감). **단, 지금 입장 코드는 이메일만 바꾸면
   운영자 계정(`admin@toffee.demo`)으로도 들어가져서**, 받은 사람이 "데모 초기화"로 데이터를 지우거나 역할을 바꿀 수 있다 → 외부에
   코드를 주기 전에 데모 서버에서 운영자 로그인을 막아야 한다(2026-10-13 확인 → **2026-10-14 반영**: 운영자는 별도 코드 `DEV_LOGIN_ADMIN_CODE`로만 — 👤 Railway에 값을 넣으면 끝, 안 넣으면 데모에서 운영자 로그인 불가). 소속사가 데모를 만져서 생긴 메시지는 다른
   소속사에게도 보이므로, 연락이 몰리는 주간엔 운영자 화면 "데모 초기화"로 가끔 되돌린다.
3. **조건은 1차 5곳 반응으로 검증** — 사전 자문은 하지 않기로 함(2026-10-13, 아이디어 노출 우려). 그래서 1차는 5곳만 보내고,
   답장·질문에서 조건(70:30·무료·비독점·3개월)에 대한 반응을 모아 2차 전에 제안서 6장과 메일을 고친다.
4. **보내는 주소** — `@toffeechat.app` 주소로 **보낼 수 있으면** 새로 만들 필요 없다(2026-10-13 사용자 확인: 회사 메일 이미 있음).
   `partners@`는 꼭 필요하진 않고, 나중에 문의 메일과 제안 메일을 나눠 보고 싶을 때 Cloudflare 전달 규칙 하나만 추가하면 된다(무료,
   새 계정 아님). 개인 Gmail 주소로 보내는 것만 피한다(스팸·신뢰도). 제안서·메일의 `[name]@toffeechat.app` 칸은 실제 쓰는 주소로 채운다.
5. **회사 표기** — 법인 전이라 "Co., Ltd."·"주식회사"를 쓰지 않는다. 서명은 "Toffee Team" + 이름.
6. 가격 칸 `฿[__]` — 벤치마킹 중인 버블의 태국 앱스토어 가격을 보고 채운다(데모의 예시 가격은 ฿99~129).
