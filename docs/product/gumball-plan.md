# 검볼(Gumball) — 예매·스트리밍권 플랫폼 기획 메모

디저트랩 아래 세 번째 서비스. 젤리(커뮤니티) → 토피(유료 1:1 메시지) → **검볼(예매)**.
이 문서는 "지금 기준으로 정한 것"만 모아 둔다. 정하게 된 이야기는
`STATUS.md` 아이디어 보관함(2026-10-22 방향 정리)과 `docs/deployment-readiness-plan.md` 2026-10-28 항목.

## 한 줄

**공정한 예매, 정가 그대로.** 판매는 일반 예매사이트처럼 대기열 → 좌석 선택, 토피 구독 팬은 먼저, 매진 뒤 취소표는 대기자 중 추첨으로 배정.
이름은 공이 하나씩 나오는 검볼 기계(= 취소표 추첨 배정)에서 따옴.

## 언제 만드나 (2026-10-28 사용자 결정)

- **운영(실제 판매)은 맨 나중** — 공연 주최사가 공식 예매처로 써 줘야 가능하고, 토피 출시(2027-02)가 먼저.
- **개발은 시간 날 때 틈틈이 미리** 해 둔다. 토피 일정을 밀지 않는 선에서.

## 정한 것 (2026-10-28)

|---|---|
| 이름 | 검볼(Gumball) 확정. 쓰기 전에 상표·도메인·앱스토어 이름 확인 |
| 대표색 | 디저트랩 한 가족 — 젤리 **퍼플**(#A888FF) · 토피 **블루**(#7C8CFF) · 검볼 **코랄**(#FF8A7A) |
| 분위기 | 바탕은 깔끔한 **흰색**(#FFFFFF, 사용자 요청), 글자·선은 코랄에 맞춘 따뜻한 톤 — 글자 #2A1612(짙은 갈색), 보조 글자 #7A5A52, 선 #F1DDD6, 연한 코랄 #FFE6DF, 흰 글자 버튼 딥 코랄 #C4432F, 어두운 화면(티켓) #3A1D17. 토피 블루는 "토피 구독 팬" 표시에만 |
| 화면 | **웹과 앱 둘 다** — 토피처럼 코드 하나로 아이폰·안드로이드·웹 |
| 저장소 | 토피와 **따로**(토피는 main에 합치면 데모가 자동 배포돼서 섞이면 위험) |
| 표 종류 | 처음부터 4개 — **지정석**(좌석 하나하나) · **스탠딩**(구역 + 입장 번호) · **비지정석**(수량) · **스트리밍권**(온라인 시청 + 다시 보기) |
| 결제 | 먼저 **가짜 결제(테스트)**로 흐름을 다 만들고, 결제대행(PG)은 나중에 연결 |
| 토피 계정 | 연결함 — "토피로 로그인". **토피 구독 팬 선예매는 공연마다 켜고 끄기** |
| 스트리밍권 판매 | **웹에서 팔고 앱은 시청만**(앱 안에서 디지털 시청권을 팔면 스토어 결제 수수료 15~30%가 붙을 수 있음). 앱 안 판매 여부는 출시 전 스토어 규칙 확인 뒤 설정으로 |
| 수수료·환불·법 | **지금 정하지 않음.** 설정값(수수료율·취소 기한·재판매 수수료·1인 매수·양도 횟수)으로 만들어 두고 나중에 숫자만. 판매자는 **주최사, 검볼은 중개**로 가정 |
| 첫 고객 | 개발엔 상관없음. 팔 때는 토피와 계약한 소속사부터 |
| 공연 등록 | **검볼 운영자가 운영자 웹에서** — 주최사는 공연·좌석도·가격·판매 일정을 보내 주기만. 주최사 전용 화면은 나중에(판매 현황·정산 보기부터, 직접 등록은 그다음). 큰 예매처도 대형 공연은 예매처 담당자가 함께 세팅하고, 직접 등록은 소규모 셀프 서비스형에서 주로 씀 |
| 판매 방식 | 판매 시작 시 **대기열** → 순서가 되면 좌석 선택(일반 예매사이트와 동일). **추첨은 매진 후 취소표 대기에만** — 회차·등급·매수 조건과 결제 수단을 등록해 두면 취소·반납 표를 조건 맞는 대기자 중 추첨 배정, 즉시 자동 결제 |
| 좌석 현황 | **실시간** — 다른 사람이 선택 중인 좌석·판매된 좌석 즉시 표시, 5분 선점 후 미결제 시 해제. 서버가 좌석 상태 변경을 같은 구역을 보는 사람에게 바로 전송(웹소켓), 대기열이 동시 입장 인원을 제한해 부하 관리. 동시에 같은 좌석을 누르는 경우는 서버가 한 명만 확정 |
| 선예매 조건 | 공연마다 판매 단계 여러 개 — 조건: 구독 중 · 연속 구독 N개월 이상 · 특정 방(개인방/CP방) 구독 · 기준일 시점 구독. 예: 3개월 이상 → 구독 팬 전체 → 일반 |
| 좌석도 | 공연장별로 한 번 제작해 재사용(배치 여러 개 가능), 공연마다 무대·사용 구역·등급·가격만 지정 — 일반 예매사이트 방식 |
| 입장 확인 | 같은 앱의 **직원 모드** — QR 스캔, 이미 입장·만료 QR 경고, 게이트별 집계, 오프라인 대비, 예매 번호 조회 |
| DB | **검볼 전용 DB**(회원·본인 인증·주문·티켓). 토피에서는 로그인과 구독 정보(구독 중 여부·연속 구독 기간)만 API로 조회 — 토피 쪽에 조회 API 추가 필요, 개인정보 제3자 제공 동의 |
| 문구 | 화면은 합니다체·짧은 명사형, 내부 페이지는 개조식. "업자 거르기" 같은 가벼운 표현 대신 "공정 예매 정책"·"부정 거래 방지" |
| 회원·예매 규칙 | 토피 계정 없이도 검볼 가입 가능(토피 연결은 선택) · 본인 인증은 첫 예매 전 · 대기열은 판매 시작 전 입장자끼리 무작위 순번, 이후 도착순 · **1인 매수 제한은 공연마다 설정**(회차 단위/공연 단위, 매수) · 취소표 대기는 공연당 1건, 동시 대기 공연 수 제한(예: 5개) |

## 공정 예매 정책 (2026-10-22 정리, 10-28 판매 방식 반영)

- 살 때: 대기열, 토피 구독 팬 선예매(기간 조건), 공연당 1인 2매 + 동행자 등록(동행자도 본인 인증 계정), 웃돈 판매 신고 보상
- 못 갈 때: 취소 기한 전엔 취소, 뒤엔 정가 반납 → 취소표 대기자 중 조건(회차·구역·매수) 맞는 사람에게 추첨 배정·자동 결제
- 선물: 지정 양도 1번(받은 사람은 반납만), 정가 이하
- 입장: 몇십 초마다 바뀌는 QR(캡처 무효, 인터넷 없이도) + 입장 직원 화면
- 해외 팬: 여권 인증·여권 영문 이름, 나라별 결제, 현지 통화·현지 시간, 9개 언어
- 매크로: 완전 차단 대신 이득 없는 구조(1인 1계정 본인 인증·2매 제한·구독 기간 선예매·실명 티켓·바뀌는 QR)

## 만드는 순서

0. **디자인 시안** — [검볼 디자인 시안](https://claude.ai/artifact/BRAJCEqErSo8ETKeCsHrfL)(2026-10-28: 브랜드 기본, 공연 상세, 대기열, 실시간 좌석 선택, 예매 완료, 내 티켓 QR, 취소표 대기, 입장 확인(직원), 운영자 공연 등록, 운영자 회원 관리)
1. 공연 등록(검볼 운영자) — 주최사 → 공연장 좌석도 → 공연·회차 → 좌석 등급·표 종류 4개 → 판매 단계·선예매 조건
2. 예매 — 대기열, 실시간 좌석 선택(5분 선점), 1인 2매, 테스트 결제
3. 내 티켓(바뀌는 QR) + 입장 확인 앱(직원 모드) + 운영자 회원 관리(검색·상세 기록·기기 초기화·티켓 무효·이용 제한, 작업 기록)·신고·문의
4. 토피 연동 — 토피 계정 로그인, 구독 정보 조회로 선예매 판정(검볼 DB는 별도)
5. 매진 후 취소표 대기(추첨 배정·자동 결제), 스트리밍 시청
6. 정가 반납 → 취소표 대기자 배정, 지정 양도
