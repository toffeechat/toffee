# 폰 없을 때 할 일 — 폰 분실·Claude/GitHub 장애 비상 계획

2026-10-27 작성. 2027년 2월부터 대표 혼자 운영하는데, 배포 승인(GitHub 앱)·Claude 앱·장애 알림(Gmail)·서비스 로그인 2단계 인증이 **전부 폰 한 대**에
묶여 있다. 출장 중에 폰을 잃어버리거나, 폰은 있는데 Claude·GitHub가 장애일 때 서비스를 지키는 방법을 미리 정해 둔다.

- 로그인 주소·아이디는 이 문서에 적지 않는다 → [사업화 장부](https://claude.ai/artifact/RinLbRwEas5gqHdZ7PzzHR) "계정" 탭.
- 비밀번호·복구 코드 값은 어디에도 적지 않는다 → 비밀번호 관리자(지금은 아이폰 "암호" 앱)와 종이 한 장에만.

---

## 1. 열쇠 지도 — 무엇이 무엇에 묶여 있나

맨 위가 막히면 아래가 줄줄이 막힌다. 그래서 **토피 Gmail과 비밀번호 관리자**를 먼저 지킨다.

```
개인 Apple ID ─── 아이폰 "암호" 앱(비밀번호·인증 코드·복구 코드 보관) ─── 아래 전부의 비밀번호
      └── Apple Developer(앱 스토어)

토피 Gmail ─┬─ 알림이 오는 곳(UptimeRobot·Sentry·운영자 알림 메일)
            ├─ Google로 로그인: Firebase·UptimeRobot·Resend·구글 로그인 설정
            └─ dev@·support@ 메일 전달(Cloudflare) ─ 로그인 링크·코드 메일: Railway·Sentry·Expo·Cloudflare

개인 GitHub ─── 저장소·배포 워크플로·운영 배포 [승인]

토피 운영자 계정 ─── 운영자 화면(점검 모드·회원 제재·환불) — 2단계 인증 앱 코드
```

| 서비스 | 하는 일 | 2단계 인증 | 폰 없을 때 들어가는 법 |
|---|---|---|---|
| **토피 Gmail** | 알림 받기, 여러 서비스 로그인 | 켜짐 — 휴대폰 번호(문자) | **백업 코드**(준비 1번) 또는 두 번째 기기의 패스키 |
| **개인 Apple ID** | 암호 앱, 나의 찾기, 애플 개발자 | 켜짐 | 신뢰할 수 있는 다른 기기(맥·아이패드) 또는 복구 키·복구 연락처 |
| 개인 GitHub | 배포·운영 승인 | 켜짐 | 복구 코드, 또는 두 번째 기기 패스키 |
| Railway | 서버·DB | 켜짐 — 인증 앱 | 복구 코드(암호 앱) |
| Cloudflare | 도메인·웹·메일 전달·백업 | 켜짐 — 인증 앱 | 복구 코드 |
| Sentry | 오류 기록 | 켜짐 — 인증 앱 | 복구 코드 |
| Expo | 앱 빌드·OTA | 켜짐 — 인증 앱 | 복구 코드 |
| UptimeRobot·Firebase·Resend | 감시·푸시·메일 | Gmail을 따름 | Gmail에 들어가면 됨 |
| **토피 운영자 화면** | 점검 모드·제재·환불 | 켜면 인증 앱 코드 | **혼자면 풀어 줄 사람이 없음** → 준비 4번 |
| Claude | 배포·수정 | Claude 계정 | 다른 기기 브라우저에서 claude.ai 로그인 |

## 2. 지금 준비할 것 (한 번, 약 1시간)

- [ ] **① 토피 Gmail 백업 코드** — Google 계정 → 보안 → 2단계 인증 → 백업 코드 → 10개 받기.
  **종이에 적어 지갑·여권 케이스에 한 장**, 암호 앱에도 한 벌. 지금 2단계 인증이 문자뿐이라, 외국에서 폰·유심을 잃으면 Gmail부터 막힌다.
- [ ] **② Gmail에 두 번째 수단** — 같은 화면에서 노트북(맥이면 Touch ID)에 **패스키** 추가. 문자보다 안전하고 폰이 없어도 된다.
- [ ] **③ 서비스별 복구 코드 위치 확인** — GitHub·Railway·Cloudflare·Sentry·Expo 복구 코드가 암호 앱에 실제로 들어 있는지 하나씩 열어 본다
  (장부엔 "별도 보관"이라고만 적혀 있음). 없으면 각 서비스 보안 설정에서 새로 받아 넣는다. GitHub는 노트북 패스키도 추가.
- [ ] **④ 토피 운영자 2단계 인증을 기기 두 대에** — 운영자 화면에서 2단계 인증을 켤 때 나오는 QR을 **폰과 다른 기기(아이패드·맥 암호 앱)에
  같이** 찍어 둔다. 이미 켜 두었으면 껐다가 다시 켜면서 두 대에 찍는다. 혼자라서 "다른 운영자가 초기화"가 불가능하기 때문(최후 수단은 4번 ⑤).
- [ ] **⑤ 인증 코드가 다른 기기에서도 보이는지** — 아이폰 "암호" 앱의 인증 코드는 iCloud 키체인으로 맥·아이패드에도 보인다.
  맥(또는 아이패드)에서 암호 앱을 열어 Railway 같은 서비스의 6자리 코드가 보이면 OK. 다른 인증 앱(Google Authenticator 등)을 쓰면 클라우드 백업 켜기.
- [ ] **⑥ Apple ID** — 설정 → 내 이름 → 로그인 및 보안 → **복구 연락처**(가족 1명) 추가. 맥이나 아이패드가 있으면 같은 Apple ID로 로그인돼 있는지 확인.
- [ ] **⑦ 출장 짐** — 노트북(암호 앱·Gmail·GitHub·claude.ai가 로그인된 상태로), 충전기, ①의 종이.

다 하면 Claude에게 "폰 분실 준비 다 했어"라고만 말하면 장부·할 일을 고친다(코드 값은 말하지 않기).

## 3. 출장 중 폰을 잃어버렸을 때 — 순서대로

1. **폰 잠그기** — 노트북이나 빌린 PC에서 icloud.com/find → 내 아이폰 → **분실 모드**(지우기는 찾을 가망이 없을 때).
2. **Gmail 들어가기** — 노트북 패스키, 또는 종이 백업 코드. → 장애 알림을 다시 받을 수 있다.
3. **노트북에서 계속 일하기** — 브라우저로 **claude.ai/code**에 들어가 평소처럼 말하면 된다(같은 배포 체계).
   운영 배포 승인은 폰 앱 대신 **github.com → 저장소 → Actions → 실행 중인 Deploy production → Review deployments → Approve**.
4. **서비스 상태 보기** — UptimeRobot 대시보드(Google 로그인), Sentry(복구 코드 또는 맥의 인증 코드).
5. **통신사** — 로밍 중 분실 신고, 귀국 후 유심 재발급(문자 인증이 그 번호로 오기 때문).
6. **돌아와서 정리**
   - 새 폰에 인증 앱 코드 옮기기(iCloud 키체인이면 자동), GitHub 앱·Gmail·UptimeRobot 앱 다시 로그인
   - 잃어버린 폰의 로그인 끊기: Google 보안 → 내 기기, GitHub → Settings → Sessions, 토피 운영자 화면은 "모든 기기에서 로그아웃"
   - **쓴 복구 코드는 새로 받기**(한 번 쓰면 끝인 코드가 많음)
   - Claude에게 "폰 바꿨어" → 장부 메모 갱신

## 4. 폰은 있는데 Claude나 GitHub가 안 될 때 — 폰만으로 할 수 있는 비상 조치

평소에는 Claude가 하지만, Claude·GitHub 장애와 서비스 장애가 겹치면 아래를 직접 한다. **고치는 게 아니라 "피해를 멈추는 것"까지만.**
고치는 건 Claude가 돌아오면 정상 절차로.

먼저 **어디가 고장인지** 본다: status.claude.com · githubstatus.com · status.railway.com · cloudflarestatus.com.

| 상황 | 폰에서 할 일 | 어디서 |
|---|---|---|
| ① 방금 배포한 뒤로 서버가 이상함 | **서버를 직전 버전으로** — 서버 서비스 → Deployments → 바로 전 성공(초록) 배포 → ⋯ → **Redeploy** | railway.com (모바일 브라우저 — 공식 앱 없음) |
| ② 웹 화면만 이상함 | **웹을 직전 버전으로** — Workers & Pages → 프로젝트 → Deployments → 바로 전 배포 → ⋯ → **Rollback** | dash.cloudflare.com (모바일 브라우저) |
| ③ 원인을 모르겠고 피해가 커짐(결제·메시지 오류) | **점검 모드 켜기** — 운영자 › 앱 설정 → 점검 모드, 안내 문구·끝 시각. 팬에겐 점검 화면, 운영자는 계속 쓸 수 있음 | 토피 운영자 화면(앱·웹) |
| ④ 앱 업데이트(OTA) 뒤 앱이 꺼짐 | 폰만으론 못 되돌림(PC 명령 필요) → ③ 점검 모드로 피해만 막고, 노트북에서 런북 8번 | — |
| ⑤ 운영자 2단계 인증 기기를 다 잃음 | 노트북에서 GitHub의 **운영 DB 데이터 수정** 절차(`ops/data-fixes/`)로 내 운영자 계정의 2단계 인증만 끄기 — 승인 2번 | github.com |

- ①·②는 데모·운영 모두 같은 방법. 운영에서 이걸 하면 "프리뷰에서 확인한 커밋만" 규칙의 **비상 예외** — 돌아와서 Claude에게 "어제 Railway에서 직접 되돌렸어"라고 알려
  기록을 맞춘다(`deployed/production` 표시가 실제와 달라져 있음).
- DB는 되돌리지 않는다(구조 변경은 "추가 먼저"라서 옛 서버도 동작 — 런북 5번).
- **연습**: 출시 전 "출장 리허설"(ops-infra-backlog "배포 자동화" C)에서 데모로 ①·②·③을 한 번씩 해 본다. 처음 하는 날이 장애 당일이 되지 않게.
